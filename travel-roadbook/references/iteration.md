# 迭代补充

路书交付后，用户回来发航班截图、补住宿、改美食、问拍摄设备，或问“完善了吗”时读本文（两个分支通用）。改完按原链接重新发布；日期或城市有变时，按 `live-data.md` 的“行程变更”同步每日任务。用 `build_roadbook.py` 生成的静态页，对应字段（`flights`、`stays`、`gear`、`bookings`）见 `scripts.md`。

## 航班截图

- 从截图读出航班号、日期、起降时间、机场与航站楼，写进页面“航班”模块；截图看不清的字段问用户，不猜。
- 逐项检查，发现问题写进该航班的备注并告诉用户：
  - **转机时长**：国际转机 < 2 小时偏紧；区分联程（一张票）与分开出票（误机无保护、常要重新值机托运，需留更宽的时间）。
  - 订票平台的“航班变动”提示列为待办，让用户去确认。
  - **凌晨航班实际是前一晚出门**（如 00:30 起飞，前一天晚上就要到机场），路书日期按出门那天写。
  - 回国转机要不要跨航站楼、换乘时间够不够。
- 行程联动：首日按红眼到达减负（先寄存行李、补觉，只排轻松项目）；返程日倒推：退房 → 到机场（国际约 3 小时）→ 退税（欧洲）→ 值机，写成当天时间轴。国内飞机 + 租车时，取还车时间与航班对齐。

## 住宿

- **已订**：写进页面“住宿”模块（状态“已订”），并按位置调路线（离换城车站远近、步行到景点、首日寄存）。
- **要推荐**：每城首选 + 备选，列起价（注明床位价还是整间、查询日期）与理由（离换城车站远近、步行到景点、设施）；名称与位置用地图工具核实，价格写来源。国内自驾加看停车位，高原看供氧与暖气。
- 检查：入住截止时间/晚到加收与当天到达时间是否冲突、首日能否寄存行李、城市税、免费取消期限、青旅要自备锁。

## 美食更新

- 落到**具体店 + 点什么**，写进当天时间轴的美食项，同步“当地美食推荐”模块（推荐店规则见 SKILL.md）。
- 逐店核对：营业日与当天是星期几（欧洲周日/周一歇业多、午晚餐间休）、是否要订位及订位规则、季节性市集是否在开。不写已知停业的店，店铺要有来源。

## 拍摄设备

- 用户要时加“拍摄与记录设备”模块：带什么（焦段、低温备用电池、存储卡与备份方案）。
- 规定：航司锂电池/充电宝限制与中国 3C 认证充电宝规定；禁拍点（如梵蒂冈西斯廷礼拜堂；寺庙殿内、部分博物馆禁拍或禁闪光）。
- 无人机：出境通常建议不带（各国注册与禁飞规定不一）；国内先查实名登记与禁飞区，以民航局规定为准。

## “完善了吗”（完成度检查）

- 回一张待办表（事项 · 状态 · 下一步），并指出先定哪件（通常先定路线，再订交通住宿、抢票、递签）。
- 逐模块过一遍还差什么：标“参考/未实测”的里程时长、未核实的价格与营业时间、未订的交通与住宿、还没到开售日的门票（按抢票日历排序）、签证材料与递签时间、节庆日期是否已和路线对齐。
