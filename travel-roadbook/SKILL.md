# 旅行路书规划（国内高德版 + 欧洲版 + 实时数据）

把用户的出行想法变成**经过核实的行程**，并产出一个手机可打开的**路书网页**；天气、汇率、预警等易变数据由每日定时任务自动刷新。

## 第一步：分流，读对应分支文档

分支规则按需读取（路径相对于本技能目录），只读命中的那一份：

| 目的地 | 分支 | 开工前完整读 |
|---|---|---|
| 中国大陆 | 国内分支（高德） | `references/domestic.md` |
| 欧洲 | 欧洲分支（Google Maps + 火车 + 签证） | `references/europe.md` |
| 其他境外 | 按欧洲分支的思路处理（地图同样走 Google Maps），签证/交通规则逐项重新核实 | `references/europe.md` |

其余文档到对应步骤再读：

| 什么时候 | 读 |
|---|---|
| 选实时模式、接入每日更新（第 5、6 步），或用户改了行程 | `references/live-data.md` |
| 用附带脚本生成静态页、自检、发布到 Cloudflare / Vercel、做二维码（第 5、7 步） | `references/scripts.md` |
| 交付后用户补航班截图、住宿、美食、拍摄设备，或问“完善了吗”（第 8 步） | `references/iteration.md` |

## 通用流程

1. **问清需求**（AskUserQuestion 一次问完，最多 4 题，已给出的不再问；用户上传了行程表先完整读完）：
   - 出发地/目的地、具体日期与天数
   - 出行方式（国内：自驾问车型/司机数/可接受单日里程；欧洲：火车公交/自驾/混合，是否已订机票、进出城市）；已订机票请用户发截图
   - 人数与构成（老人小孩、行动限制、国内问是否上高原）；**同行者是否都有同组织的 claude.ai 账号**（决定实时模式，见 `references/live-data.md`）
   - 偏好、必去、**想赶上的节庆**、**明确不想去的地方**、住宿档次与预算；欧洲加问护照国籍与已有签证
2. **核实与质疑**（核心价值，不能省）：按分支文档的“校验规则”逐条校验。发现问题要明确指出、给替代方案和数字对比，关键取舍让用户拍板后再定稿，不要默默照做。
   - **节庆日期对齐**（两个分支都要做）：查清沿途节庆、大型活动当年的确切日期（狂欢节、圣诞集市、泼水节、那达慕等常随复活节、农历或固定周末浮动，不能按往年猜），和逐日路线对到“那天人在哪座城”。想赶的没赶上，或顺路撞上不想遇到的（人潮、房价翻倍、封路、闭馆），属于必须第一时间告诉用户的问题，给调整方案让用户拍板；结论写进封面关键标签。
3. **采集信息**：按分支文档的工具链。
4. **生成地图链接**：国内 amapuri（自驾加每站导航链接），欧洲 Google Maps；链接规则见分支文档。
5. **构建路书网页**：单文件自包含 HTML，手机优先，模块见分支文档的“页面模块”。
   - 支持 Artifact 的环境：先加载 artifact-design 技能，**再按 `references/live-data.md` 加载 artifact-capabilities 技能接入实时数据**，发布为 Artifact。
   - 用户要不登录也能打开的公开链接或自定义域名：发布到 Cloudflare Pages / Vercel（`scripts/deploy.sh`）。
   - 都不行：交付 HTML 文件（无实时能力，页面注明数据查询日期）。
   - 静态版可直接用 `scripts/build_roadbook.py` 从 JSON 生成（国内高德、国外 Google Maps 都支持），用法与字段见 `references/scripts.md`。
   - 自检：手机宽度无横向滚动、按钮链接可点、深色模式可读；环境里有 Playwright 时用 `scripts/check_page.py` 自动检查并看截图。
   - **发布前查脚本**：页面有内联脚本时跑一次 `node --check`（`check_page.py` 会逐个检查，`deploy.sh` 发布前也会自动查）。手写页面最常见的错是 JS 单引号字符串里的撇号没转义（Wombat's、All'Arco、L'Aquila、d'Orsay），整页脚本会直接失效：要么转义，要么把数据放进 `<script type="application/json">` 再 `JSON.parse`，别把地名、店名拼进 JS 字符串。
6. **接入实时更新**：按 `references/live-data.md` 写入初始数据、建每日定时任务、做一次功能校验。
7. **交付**：最终回复 ≤300 字，说明模块、数据查询日期、**自动更新的时间与截止日**；远期价格（欧洲加罢工）出发前再核实；列出需要去抢的预约（按开售日期排序，写具体日期与北京时间）。定时任务若需手动批准才能写数据，提醒用户在该任务设置里打开“自动批准”。用户要扫码分享时，用 `scripts/make_qr.py` 为发布后的 https 链接生成二维码。
8. **迭代补充**：交付后用户回来补航班截图、住宿、美食、拍摄设备，或问“完善了吗”，按 `references/iteration.md` 处理，改完原链接重新发布。

### 内容口径（两个分支共用，硬要求）

- **不编造**：里程、时长、天气、门票价格、开放/开售时间必须来自工具或可追溯来源；查不到写“以官方为准”或留空。
- 价格标注币种、查询日期与“节假日/旺季可能浮动”；区间车、索道、骑马等二次消费单列。
- 美食写当地真实特色且符合**当季**，每站 3–4 项（时间轴里一句速览），详情放“当地美食推荐”模块，规则见下。
- 穿着按**最低夜温 + 场景**分层（速干内层/抓绒/冲锋衣/羽绒），并给防晒、雨具、鞋履。
- 每天至少一个标注“可选”的项目，允许体力或天气变化时砍掉。

### 当地美食推荐（两个分支共用）

- **选菜**：每个过夜城市 2–4 道当地代表菜/小吃，符合当季；每道一句“是什么、怎么吃”，用标签标注辣度、忌口（清真、生食、内脏、酒精）、早餐/夜宵等场景。
- **推荐店**：每道菜 0–2 家，**必须用地图工具查实**，不凭记忆写店名：
  - 国内：高德 `maps_text_search`（`keywords` 为菜名或店名、`city` 为城市）取店名、地址、poiId；坐标用 `maps_geo` 或 POI 结果。
  - 国外：Google Maps 地点检索取名称、地址、评分、价位、营业时间、place_id。
  - 只写工具或可追溯来源给出的信息；评分注明来源（如“Google 4.5”），查不到的字段留空。
- **怎么挑**：靠近当天路线或住宿（写步行距离）、本地人常去，避开景区门口高价店；写人均/价位、营业时间与休息日（欧洲午晚餐间休、周日/周一歇业多）、是否需预约。
- **导航链接**：
  - 国内：`https://uri.amap.com/marker?position=经度,纬度&name=店名&src=roadbook&coordinate=gaode&callnative=1`（已装高德时唤起 App）。
  - 国外：`https://www.google.com/maps/search/?api=1&query=店名+城市&query_place_id=<place_id>`。
- 模块末尾注明数据来源与查询日期；价格和营业时间以店家当日为准。
